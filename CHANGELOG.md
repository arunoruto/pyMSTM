## 2.1.0 release notes

### New

- **Multithreaded periodic-lattice solves.** `MstmBindings(n_threads=...)`
  (also settable between solves, `m.n_threads = 4`) and
  `MstmTask(n_threads=...)` compute the sphere-pair lattice sums, nearly all
  of a lattice solve's time, on several cores with OpenMP. Results are
  bit-identical to a serial solve for any thread count. Default 1 (the 2.0
  behaviour); `0` = all CPUs of the process, a float in (0, 1] a fraction
  of them, negative = all but that many (`pymstm._mstm.resolve_n_threads`,
  the same convention as pyfastmm). `OMP_NUM_THREADS` does not limit it.
  Measured on 100 iron spheres in a 160 nm cell (i9-9900K): 152 s serial,
  77 s with 2 threads, 40 s with 4. Clusters without a lattice and layered media are unchanged
  (serial).
- `solve_task(task, isolate=True)` passes `n_threads` to the child process;
  `run_dask(..., resources={"cores": 4})` forwards Dask worker resources,
  so a task that uses a whole 4-core worker runs one per worker at a time
  (workers started with `--resources "cores=4"`). See the README section
  "Several cores for one lattice solve".

### Packaging

- The extension is built with `-fopenmp`; the Linux wheels bundle the GNU
  OpenMP runtime `libgomp` next to `libgfortran` (GPL-3.0-or-later WITH
  GCC-exception-3.1, see `LICENSES/gfortran-runtime.txt`).
- The Fortran changes are a patch on MSTM's `mstm-modules-33.f90`
  (`src/pymstm/_fortran/patches/mstm-modules-33-openmp-lattice.patch`,
  with a description of what was made thread-safe and why); the MSTM
  command-line program still builds from the unmodified sources.

## 2.0.0 release notes

pyMSTM 2.0 adds a high-level, validated `MSTM` model that runs through the
bindings or MSTM's command-line program, physical cross sections for
spheres in a medium, distributed solves with Dask, and fixes for periodic
lattices and layered media.

### Breaking changes

- **Physical cross sections in a medium.** With a medium refractive index
  `n` other than 1, efficiencies are now per incident irradiance in the
  medium: MSTM's own values divided by `Re(n)` (`get_mie_efficiencies()`:
  by `Re(n)**2`). A single sphere now gives the Lorenz–Mie efficiencies in
  the host. `cross_section_convention="mstm"` (on `MstmBindings(...)`,
  `MSTM` and `MstmTask`) returns the 1.x numbers. Vacuum is unchanged.
- **Renamed classes.** The bindings class `MSTM` of 1.x is now
  `MstmBindings`; `MSTM` is the new high-level model.
- **Periodic lattices.** `set_lattice` cell widths are now scaled by
  `set_length_scale`, like radii and positions (and like the CLI's
  `cell_width`); before, a cell given in physical units was used
  unscaled. Lattice efficiencies are now per unit-cell area, as in the
  CLI, so `qabs_tot` is the unit-cell absorptance; before, they were per
  volume-equivalent sphere area.
- **One `MstmBindings` at a time.** MSTM's state is process-global, so
  only the most recently created instance can be used; an older one raises
  `RuntimeError` instead of silently computing with, or freeing, the newer
  one's state.
- **Removed:** `MstmBindings.get_scattering_matrix()` (non-deterministic
  results; loop over `get_scattering_angle()`), the ignored
  `MstmBindings(library_path=)` and `set_incident(direction=)` arguments
  (the direction follows from `beta_deg`, above 90 degrees the wave comes
  from the far side), `pymstm._build`, and the `dashboard` and `dev`
  extras (`dev` is a dependency group now).
- `compute_tmatrix()` no longer leaves `tmatrix_temp.dat` in the working
  directory; pass `tmatrix_file=` to keep the file for
  `ranorient_smatrix()`.

### New

- `MSTM`: a pydantic model of a whole problem; `solve()` returns an
  `MstmResult` (totals, per sphere, optional Mueller-matrix samples as a
  phase function), the same through the bindings and with `cli=True`
  through the MSTM command-line program.
- `run_mstm()`, `find_mstm_binary()`: run the MSTM program (serial or
  MPI) from Python; `write_inp_file()` gains `scattering_map_dimension`,
  `normalize_s11`, `random_orientation` and `incidence_average`.
- `s11_to_phase_function()`, `cli_normalized_s11_to_raw()`.
- `MstmTask`, `solve_task()`, `run_dask()`: independent solves on a Dask
  cluster (`pymstm[dask]`), optionally each in a fresh process.
- The Fortran solves release the GIL; `MSTM_LOCK` serialises them.
- A Nix flake output for the Python package (`.#pymstm`).

### Fixes

- Periodic lattices with more than 31 propagating diffraction orders
  corrupted the heap.
- A second layered solve in the same process reused the first geometry's
  sphere–boundary matrices (wrong results, or heap corruption).
- The CLI output parser returned no totals for `incidence_average` runs.

### Packaging

- Linux x86_64 wheels for CPython 3.11–3.14; `__version__` comes from the
  package metadata.
- The sdist no longer contains MSTM's documentation, examples and older
  code (26 MB to 0.4 MB), nor the GPL-licensed routine in upstream's
  `random_configuration-10.f90`: pyMSTM compiles its own copy with an
  independent replacement.
- Licences: `LICENSE` (pyMSTM, MIT) and `LICENSES/` (MSTM and the routines
  it includes; the GNU Fortran runtime bundled in the wheels).
- `CITATION.cff`.
